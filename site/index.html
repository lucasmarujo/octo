recursos03

feito para quem roda dez agentes de uma vez.

03.1

escreva a tarefa. o agente nasce.

Escolha a pasta com ctrll e quem executa com tab. Escreva a tarefa e aperte enter: o agente já começa trabalhando nela e aparece no grupo do projeto, com o tempo e a frase do que está fazendo.

03.2

um deles precisa de você.

Quando um agente que você não está olhando pede uma aprovação ou termina, o terminal toca o sino, mostra a notificação e o título da janela conta quem espera, mesmo com o orkai em segundo plano.

03.3

altn e você está lá.

Abre direto o agente que espera há mais tempo, de qualquer tela, até de dentro de outro agente. Quer o aviso no celular? Um notify_command manda pelo ntfy ou para onde você quiser.

03.4

dois agentes. um repo.

Com ctrlt, cada agente nasce numa worktree do git, na branch orkai/<nome>. Vários agentes mexem no mesmo repositório sem pisar um no outro. /diff mostra o que mudou; /merge traz para a sua branch.

03.5

reiniciou a máquina?

Cada agente roda num processo próprio, dono do terminal dele: fechar ou atualizar a interface não derruba ninguém. Depois de um reboot, ctrlr retoma cada conversa de onde parou.

03.6

estado exato, na hora.

Hooks, plugins e o protocolo de cada agente dizem ao orkai quando ele está trabalhando, esperando você ou terminou. Sem adivinhar pelo texto da tela: uma resposta que termina com “Would you like to…?” não vira pergunta.

Os hooks só gravam o tipo do evento. O prompt, os comandos e as respostas nunca vão para o disco.

03.7

consumo dos planos à vista.

As janelas de 5 horas, semana e mês (ou o saldo) de cada agente em que você está logado, com a contagem até o reset. Verde, amarelo a partir de 70%, vermelho a partir de 90%. Quem não tem login não aparece.

  • skills no /

    As skills e os comandos de cada agente aparecem no autocomplete. /skill argumentos inicia um agente já invocando a skill.

  • subagents à vista

    Os subagents que o Claude Code e o Codex disparam aparecem logo abaixo do agente, com a descrição e a ferramenta em uso.

  • !comando

    !npm run dev roda o comando num terminal novo, sem trocar quem executa as próximas tarefas.

  • terminal que vira agente

    Rodou claude dentro de um terminal? Em até 2 segundos ele aparece no overview com tipo, estado e subagents.

  • remote control

    Todo Claude Code iniciado pelo orkai abre com Remote Control ligado: continue a sessão no app do Claude ou em claude.ai/code.

  • atualiza sozinho

    Cada build nova é conferida por tamanho e SHA-256 antes de substituir o executável. Os agentes em execução não são afetados.

como funciona05

a interface vai e volta. os agentes ficam.

Cada agente roda dentro de um processo holder próprio e destacado, dono do pseudo-terminal (ConPTY no Windows, PTY no Unix). A interface só se conecta a eles.

interfaceorkaipode fechar, travar ou atualizar
127.0.0.1 + token
holderConPTY / PTY⠋ claude
holderConPTY / PTY⠋ codex
holderConPTY / PTY⠋ pwsh / bash
  • fechou?

    Fechar, reiniciar ou atualizar o orkai não derruba nenhum agente. Ao abrir de novo, ele reconecta em todos.

  • ↻ reboot?

    O agente aparece como interrompido e ctrlr relança cada um na sua pasta, retomando a conversa.

  • e o histórico?

    Toda a saída de cada agente é gravada, com rotação. orkai logs <id> imprime a transcrição.

experimente: aperte enter, tab ou altn agora

  • enterinicia um agente com a tarefa digitada
  • tabescolhe quem executa: um agente ou o terminal
  • ctrllescolhe a pasta do projeto
  • ctrltliga a worktree própria para os próximos agentes
  • altnabre o próximo agente esperando você
  • ctrl]volta da aba do agente para a visão geral
  • ctrlrrecupera os agentes interrompidos
  • !cmdroda o comando num terminal novo
  • /comandos do orkai e skills do agente
também na linha de comando
orkai ls [-s sessão]             lista agentes com o estado ao vivo
orkai new -k <agente> -C <pasta> inicia um agente com uma tarefa
orkai send <id> <texto...>       digita no agente e aperta enter
orkai attach <id>                usa o terminal atual direto no agente
orkai logs <id> [-n linhas]      transcrição gravada do agente
orkai recover [-s sessão]        relança agentes interrompidos
orkai update                     baixa e instala a build mais nova
segurança07

seu código, sua máquina.

  • 127.0.0.1

    Os holders escutam só em localhost, numa porta aleatória.

  • 256 bits

    Um token por agente, guardado só na sua pasta de dados.

  • 0

    arquivos de configuração seus alterados. Hooks e plugins valem só para o processo lançado.

  • SHA-256

    conferido, com o tamanho, em cada atualização antes de trocar o binário.

Para mostrar o consumo, o orkai lê o token de login de cada agente só em memória e o envia apenas, por HTTPS, ao serviço que o emitiu. Ele nunca é gravado, registrado em log ou renovado pelo orkai.

instalar08

instale em um minuto.

target=orkai-x86_64-unknown-linux-musl
mkdir -p ~/.local/bin
curl -fL -o ~/.local/bin/orkai "https://github.com/lucasmarujo/orkai-cli/releases/download/latest/$target"
chmod +x ~/.local/bin/orkai

Se ~/.local/bin ainda não estiver no PATH, adicione export PATH="$HOME/.local/bin:$PATH" ao ~/.bashrc ou ao ~/.zshrc. O binário é estático e roda em qualquer distro.

target=orkai-aarch64-apple-darwin
mkdir -p ~/.local/bin
curl -fL -o ~/.local/bin/orkai "https://github.com/lucasmarujo/orkai-cli/releases/download/latest/$target"
chmod +x ~/.local/bin/orkai

Mac com Intel: troque o target por orkai-x86_64-apple-darwin. Se ~/.local/bin ainda não estiver no PATH, adicione export PATH="$HOME/.local/bin:$PATH" ao ~/.zshrc.

$dir = "$env:LOCALAPPDATA\Programs\orkai"
$url = "https://github.com/lucasmarujo/orkai-cli/releases/download/latest/orkai-x86_64-pc-windows-msvc.exe"
New-Item -ItemType Directory -Force $dir | Out-Null
Invoke-WebRequest $url -OutFile "$dir\orkai.exe"
$path = [Environment]::GetEnvironmentVariable("Path", "User")
if ($path -notlike "*$dir*") { [Environment]::SetEnvironmentVariable("Path", "$path;$dir", "User") }

Rode no PowerShell. Depois abra um terminal novo e digite orkai no PowerShell, Bash ou zsh.

git clone https://github.com/lucasmarujo/orkai-cli.git
cd orkai-cli
cargo install --path .

Com Rust 1.88+, vai para ~/.cargo/bin. Builds locais aparecem como dev e não se auto-atualizam; orkai update converte uma delas em build oficial.

importante

Para usar um agente de IA, o programa dele precisa estar no PATH: claude, codex, kilo, opencode, agy, grok, qwen ou kimi. Deixe o orkai numa pasta em que o seu usuário possa escrever: a atualização automática substitui o próprio executável.
