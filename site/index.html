Ten tabs, six projects. You flip between them to find out who finished, who got stuck and who asked for approval twenty minutes ago.

Octo brings every agent from every project into one window, grouped by folder, with each one's status live. When one of them needs you, it lets you know.

features02

built for running ten agents at once.

02.1

type the task. the agent spawns.

Pick the folder with ctrll and who runs it with tab. Type the task and press enter: the agent starts working on it right away and shows up in the project's group, with its timer and a line saying what it's doing.

02.2

one of them needs you.

When an agent you're not looking at asks for approval or finishes, Octo chimes, shows a notification and the window title counts who's waiting, even with Octo in the background.

02.3

altn and you're there.

Jumps straight to the agent that's been waiting the longest, from any screen, even from inside another agent. Want it on your phone? ctrlp pairs it, end-to-end encrypted, and a notify_command sends the alert through ntfy or wherever you like.

02.4

two agents. one repo.

With ctrlt, each agent spawns in its own git worktree, on the orkai/<name> branch. Multiple agents work on the same repository without stepping on each other. /diff shows what changed; /merge brings it into your branch.

02.5

rebooted your machine?

Each agent runs in its own process, which owns its terminal: closing or updating the interface takes no one down. After a reboot, ctrlr resumes every conversation right where it left off.

02.6

exact status, instantly.

Hooks, plugins and each agent's own protocol tell Octo when it's working, waiting for you or done. No guessing from screen text: a reply that ends with “Would you like to…?” isn't mistaken for a question.

Hooks only record the event type. Your prompts, commands and responses never touch the disk.

  • skills on /

    Each agent's skills and commands show up in autocomplete. /skill args starts an agent that invokes the skill right away.

  • subagents in view

    The subagents that Claude Code and Codex spawn show up right below their agent, with their description and the tool in use.

  • !command

    !npm run dev runs the command in a new terminal, without changing who runs your next tasks.

  • terminals that become agents

    Ran claude inside a terminal? Within 2 seconds it shows up in the overview with its type, status and subagents.

  • remote control

    Turn on Remote Control in the composer and the Claude Code sessions Octo starts can be picked up in the Claude app or at claude.ai/code.

  • self-updating

    Every new build is verified by size and SHA-256 before it replaces the executable. Running agents aren't affected.

how it works04

the interface comes and goes. the agents stay.

Each agent runs inside its own detached holder process, which owns the pseudo-terminal (ConPTY on Windows, PTY on Unix). The interface just connects to them.

  • closed it?

    Closing, restarting or updating Octo takes down no agent. When you open it again, it reconnects to all of them.

  • ↻ reboot?

    Agents show up as interrupted and ctrlr relaunches each one in its folder, resuming the conversation.

  • and the history?

    Every agent's full output is recorded, with rotation.

security06

your code, your machine.

  • 127.0.0.1

    Holders listen on localhost only, on a random port.

  • 256 bits

    One token per agent, stored only in your data folder.

  • 0

    of your config files changed. Hooks and plugins apply only to the launched process.

  • SHA-256

    verified, along with the size, on every update before the binary is swapped.

To show usage, Octo reads each agent's login token in memory only and sends it, over HTTPS, solely to the service that issued it. Octo never stores, logs or refreshes it.

download07

download Octo.

One file for your system, with no admin rights. Octo updates itself to every new version, checked by size and SHA-256, and closing it never stops an agent.

  • windows 10 and 11 · x64WindowsOcto-setup.exe

    Installs Octo for your user, with a Start menu shortcut; running it again upgrades Octo, even while it's open. Not code signed yet: if SmartScreen warns, choose More info › Run anyway. Rather not install? Octo.exe runs from any folder your user can write to.

  • macos 11+ · apple siliconmacOSOcto-macos-apple-silicon.zip

    Unzip it and drag Octo to Applications. Signed and notarized by Apple, so it opens like any other app.

  • macos 11+ · intelmacOS IntelOcto-macos-intel.zip

    The same app for Macs with an Intel chip, signed and notarized the same way.

  • linux · x64LinuxOcto-linux-x86_64

    Needs WebKitGTK 4.1 (libwebkit2gtk-4.1-0, on Ubuntu 22.04 and newer). Make it executable with chmod +x and run it.

getting started

  1. Open Octo: every agent shows up on the board, by status.
  2. Pick the project folder in where, or with ctrll.
  3. Pick who runs it in who, or with tab.
  4. Type the task and press enter: the agent starts already working on it.
  5. Click a card to open the agent; altn opens the one waiting for you and ctrl] goes back to the board.
important

To use an AI agent, its CLI must be installed and on your PATH: claude, codex, kilo, opencode, agy, grok, qwen, kimi or pi. Octo starts each one in the project folder you pick.
